# pearljs gaps found while building the dashboard

Things the dashboard needed from pearljs and had to work around. None of them is patched here.

1. Certificate version 4 (FP8) is not parsed. Pearl's testnet moved to V4 certificates at height 67370 on 2026-11-17 (branch `fp8-scheme`), so `parseBlock`, and with it `followChain`, stops there on testnet. Mainnet and testnet2 are still on V3, so the dashboard is unaffected on mainnet until the FP8 fork reaches it. The dashboard stores `cert_version` and `cert_kind` as reported and will show V4 once pearljs parses it; `isMoECertificate` will need a rule for V4 too.
2. No CA-trusting `fetch` outside the test kit. pearld serves RPC over TLS with a self-signed `rpc.cert`, and Node's `fetch` takes a CA only through an undici dispatcher. `trustingFetch` exists, but only in `pearljs/testing-regtest`, which is documented as test-only. The dashboard carries its own copy (`src/node.ts`). A `pearldFetch(ca)` or a `ca` option on `PearldClient` would remove that.
3. `spendableUtxos` (and so `payFromAccount`) defaults `coinbaseMaturity` to `COINBASE_MATURITY` (100), not to `network.coinbaseMaturity`. On a `customNetwork` with a short maturity, a coinbase output with enough confirmations is still refused unless `coinbaseMaturity` is passed again. Found in the dashboard's co-spend test.
4. No helper for the miner's text in a coinbase script. `inspectTransaction` returns the script and the BIP 34 height; the dashboard pulls printable runs out of the rest itself (`coinbaseTag` in `src/facts.ts`). A `coinbaseText(script)` that skips the height and extra-nonce pushes would be more exact.
